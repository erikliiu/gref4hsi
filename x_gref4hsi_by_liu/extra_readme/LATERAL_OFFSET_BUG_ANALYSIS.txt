LATERAL OFFSET BUG - ROOT CAUSE AND FIX
========================================

PROBLEM SUMMARY:
----------------
Georeferenced HSI data has a lateral (cross-track) offset of ~2.47m from the navigation trajectory.
The georef swath appears to the LEFT of the trajectory when it should be centered beneath it.

DIAGNOSIS:
----------
Running debug_lateral_offset.py and analyze_georef_offset.py revealed:

1. Vehicle heading SOUTH (yaw ≈ 180°)
2. Camera offset from nav body: (-2.47m East, +0.34m North) 
3. Expected camera offset: Should be ~(0, -2.5m) since camera is 2.5m forward
4. Actual result: Camera appears 2.47m WEST of the vehicle

When vehicle heading is NORTH (yaw = 0°):
- Body X (forward) → World (0, 1, 0) = North ✓ CORRECT
- Body Y (starboard/right) → World (-1, 0, 0) = West ❌ WRONG! Should be East

ROOT CAUSE:
-----------
The body frame definition has an incorrect sign convention for the Y-axis (starboard).

Current behavior:
- Body +Y (starboard/right) maps to WEST when heading North
- This causes a left/right flip in the georeferencing

Expected behavior:
- Body +Y (starboard/right) should map to EAST when heading North
- Standard right-handed coordinate: +X forward, +Y right, +Z up

POSSIBLE FIXES:
---------------

Option 1: Fix the yaw rotation matrix
--------------------------------------
In utils/utils.py, euler_to_rotation_matrix_nav(), the Rz matrix may need a sign flip:

Current:
```python
Rz = [[cos(yaw), -sin(yaw), 0],
      [sin(yaw),  cos(yaw), 0],
      [0,         0,        1]]
```

This is the standard CCW rotation matrix. But if the body frame convention is different,
we might need:

```python
Rz = [[cos(yaw),  sin(yaw), 0],
      [-sin(yaw), cos(yaw), 0],
      [0,         0,        1]]
```

ROTATION_HSI_TO_BODY = np.array(
